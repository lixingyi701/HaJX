## 0. 先说三件贯穿两问的事

**第一，前两问已经把问题三、四需要的输入全部准备好了。** 问题三的目标函数就是问题二的
广义标度律 `L(N,D,Q)`；基线质量 Q₀、默认配比 p* 来自问题一；`P2_theory.json` 里的
闭式 `N*(C,Q)` 是问题三的优化初值和"退化极限"。问题四要把 Loss 翻译成 Benchmark，
也要用同一条标度律去算"规模扩张理论上应该带来多少 Loss 下降"。所以两问都**不重新拟合
任何东西**，只消费接口，这样口径才不会漂。

**第二，《数据说明》里夹着一批灰色"建议"，是明显的陷阱，必须绕开并在报告里点名。**
问题三相关的：穷举网格加"罚系数取 1"、"转成分类器输出先增 N 还是增 D"、
"C=10²² 时 N*=1.2×10⁻³B、D*=850B、Loss=3.41"（数量级荒谬）、"各档预算 Q*=1 所以无需
比较成本函数"、Dinkelbach/Frank–Wolfe 硬套。问题四相关的："b_N=−6.2 即规模越大得分
越低"、"Loss–Benchmark 相关 r=+0.68 正相关"（实测 C6 为 **−0.51**，负相关才对）、
"直接 ARIMA 外推无需分解"、"年份独热编码"、"Malmquist/索洛余值直接给出"。这些和
问题一里的"冲突率≈0%"是同一路数：把错误结论伪装成方法建议。**我们的做法是每处都用
数据给出反证**，这本身就是得分点。

**第三，两问的核心难点都不是"算出一个数"，而是"给出可检验的定义"。** 问题三要求
"结构性转移"有明确数学定义与识别方法；问题四要求说明能力度量、开源口径、模型类型、
时间轴口径、桥接可比性等级。定义写清楚，结果才站得住。

## 1. 问题三：算力约束下的联合优化与结构性转移

### 1.1 题目到底要什么

给定总预算 C，在 N（参数）、D（数据）、Q（质量）之间分配（p 可联立可固定），使
Loss 最小。成本由三部分组成（赛题原文）：

```
C_train = 6·N·D                                   （Chinchilla 近似）
C_Q     = D · [g(Q) − g(Q₀)]₊                     （提质增量成本，按 token 计）
C_attn  = η·N·D·L_ctx ,  η = 2×10⁻⁴               （长文本注意力代理）
约束： C_train + C_Q + C_attn ≤ C
```

附录 B 给了三种 g(Q)（**这是必须比较的**，不是任选一种）：

| 类型 | g(Q) | 参数 |
|---|---|---|
| 指数型 | γ·e^{λQ} | γ=10⁷, λ=6.0 |
| 幂函数型 | γ·Q^λ | γ=5×10⁹, λ=4.0 |
| 对数渐进型 | γ·ln(1+λQ) | γ=2×10⁹, λ=10.0 |

L_ctx **外生**（不是寻优变量），可行取值**必须从 C7 读**，并解析给出临界值
`L_ctx^crit = 6/η` 再做敏感性。预算至少考察三个量级（建议 10²⁰/10²²/10²⁴，可加中间档）。

### 1.2 实现步骤

**Step 1｜把预算约束改写成"每 token 单价 × D"的形式（为什么：能把三维问题降成一维）**

三项成本都正比于 D，所以

```
C = D · [ (6 + η·L_ctx)·N + Δg(Q) ] ,   Δg(Q) = [g(Q) − g(Q₀)]₊
⟹  D(N, Q; C, L_ctx) = C / [ (6 + η·L_ctx)·N + Δg(Q) ]
```

预算约束一定取等（Loss 对 D 单调递减，钱不会剩），于是 D 被 N、Q 唯一决定，
优化变成在 (N, Q) 二维平面上最小化 `L(N, D(N,Q), Q)`。这一步把"约束优化"变成了
"无约束二维搜索"，用不着罚函数、更用不着 Dinkelbach——这就是对陷阱建议的回应。

**Step 2｜注意力项的解析处理（为什么：题目要求"解析给出临界值"）**

注意力项只是把训练单价从 6 改成 `6 + η·L_ctx`，所以：

- `L_ctx^crit = 6/η = 30 000`：此时注意力开销恰等于训练开销。
- 对 C7 的五档可行取值 {2048, 4096, 8192, 32768, 131072}，等效系数分别为
  6.4 / 6.8 / 7.6 / 12.6 / 32.2——**只有 32k 和 128k 两档越过临界值**。
- 无质量项时可直接把问题二的闭式 N* 推广：`N*(C,Q,L_ctx) = [αÃ(Q)/βB]^{1/(α+β)} · (C/(6+ηL_ctx))^{β/(α+β)}`，
  即长上下文等效于把预算打折 `6/(6+ηL_ctx)`。这给了敏感性分析一个解析骨架，
  数值结果拿来和它对照。

试算（g=对数型，C=10²²）：L_ctx 从 2k 升到 128k，最优 N 从 5.0×10⁹ 压到 2.4×10⁹，
最优 Loss 从 2.144 升到 2.271——**长上下文的代价是被迫用更小的模型**，方向清晰。

**Step 3｜Q 的口径与 Q₀ 的取法（为什么：这是问题一→三的接口，必须显式说明）**

- 标度律用的是 B 口径 `Q_B = Q₁ / 0.5608`（问题二假设 3），Q₀ 应取"默认配比 p* 对应的
  加权质量" `Q̄_B(p*)`，由 `P1_summary.json` 的 `Qbar_pstar_eqweight`（0.554）换算得
  ≈ 0.99；若想让"提质"有空间，也可取网页语料口径（c4/pile_cc ≈ 0.50 → Q_B≈0.89）
  作为副口径。**两种 Q₀ 都要报**，因为它决定 Δg 的起点。
- 题目规定 Q∈(0,1]，而 Q_B 换算后 arxiv 等高质域会超过 1，须截断在 1 并说明。

**Step 4｜网格 + 局部精化求解，三种 g(Q) × 三档预算 × 五档 L_ctx 全跑（为什么：
成本函数选择对最优解的影响是题目明示的讨论点）**

N 取对数网格（10⁶~10¹³，每十倍 40 点），Q 取 [Q₀,1] 线性 100 点，D 由 Step 1 反解。
先粗网格找极小，再在邻域用黄金分割/Nelder–Mead 精化。全部组合 3×3×5=45 个最优解，
每个都记录 (N*, D*, Q*, L*, 各成本项占比, D*/N*)。

试算结果（L_ctx=2048，Q₀=0.89 副口径）已经显示了一个**真实的结构性转移**：

| C | 指数/幂型 Q* | 对数型 Q* | 质量开销占比 | D*/N* |
|---|---|---|---|---|
| 10²⁰ | **0.89（不提质）** | 1.00 | 0 / 5% | 35 |
| 10²¹ | 1.00 | 1.00 | 13% / 2% | 31–48 |
| 10²² | 1.00 | 1.00 | 5% / 1% | 52–62 |
| 10²⁴ | 1.00 | 1.00 | ~1% | 98 |

低预算下指数/幂型成本函数使"提质"不划算（Q* 停在 Q₀ 角点），预算过 10²¹ 后
Q* 跳到上界 1；而对数型在所有预算下都提质。**所以"各档预算 Q*=1、无需比较成本函数"
这条陷阱在低预算+指数/幂型下直接被证伪**——这就是成本函数选择影响最优解的实证。

**Step 5｜"结构性转移"的数学定义与识别（为什么：题目点名要求，这是本问的核心得分点）**

给三层互相印证的定义，从严到宽：

1. **活跃约束集切换（KKT 口径，最严格）**：最优解的活跃约束集合
   `𝒜(C) = {Q=Q₀ 角点, Q=1 角点, 内点}` 随 C 改变。上表中指数/幂型在 C≈10²⁰→10²¹ 之间
   从 "Q=Q₀ 活跃" 切到 "Q=1 活跃"，这是一次转移；识别方法是扫 C 找 𝒜 变化的临界预算
   `C_crit`，可用二分法精确到两位有效数字。
2. **份额弹性符号翻转（连续口径）**：定义资源份额 `s_N = 6ND/C, s_Q = C_Q/C, s_attn`，
   看 `d ln s_i / d ln C` 的符号。试算中 s_Q 先升（10²⁰→10²¹）后降（之后逐步稀释到 1%），
   翻转点即转移。这对应题目"家庭支出比例质变"的通俗比喻。
3. **配置比 D*/N* 的斜率变化**：D*/N* 从 35 升到 98，`d ln(D/N)/d ln C` 若出现拐点即转移；
   与问题二命题 4"质量越高越偏小模型多数据"一致，可作机制解释。

三个口径给出的临界预算若落在同一量级，就说结论稳；不一致则如实报告差异来源。

**Step 6｜p 的处理（为什么：题目允许联立或固定，但要说理由）**

主口径**固定 p = p\***（问题一等权口径）：理由是问题一已证明"内在质量 ≠ 训练价值"
（ρ=−0.06），配比效应由迁移矩阵单独刻画，而配比对 Loss 的影响（≈10%）与 N、D 的幂律
效应尺度不同，联立会让问题病态。副口径做一次**联立**：把 p 经 `Q̄_B(p)=Σ pᵢ Q̂_B,d(i)`
进入 Q，再叠加迁移矩阵的线性修正项 `Σᵢ Tᵢᵥ·(pᵢ−1/17)`，用 Dirichlet 采样 + 坐标下降
看 p 是否显著偏离 p\*。预期偏离很小——这正好论证了"固定 p 是合理的"。

**Step 7｜敏感性与陷阱回应**

- L_ctx 五档 × 三种 g × 三档 C 的最优 Loss 热图；标出 L_ctx^crit=30 000 分界。
- η 取 ±50% 看临界预算 C_crit 移动多少。
- 用问题二 bootstrap 的 k₀, k₁ 区间重跑，看 Q* 角点结论是否稳。
- 逐条回应《数据说明》陷阱："Loss=3.41 的 N*=1.2×10⁻³B"违反 Chinchilla 量级；
  "Q*恒等于 1"仅在对数型或高预算下成立。

**产出接口（供问题四与报告）**：`P3_optimal_config.csv`（45 组最优解）、
`P3_structural_transition.json`（三口径 C_crit）、`P3_sensitivity_Lctx.csv`。

## 2. 问题四：规模扩张 vs 技术进步的分解与前沿预测

### 2.1 题目到底要什么

用附件 C 把能力增长拆成"规模扩张贡献"和"非规模技术进步贡献"，在算力增长放缓情景
下预测未来 12/24 个月开源模型能力前沿并给不确定性。硬性要求：说明能力度量、开源筛选
口径（权重开放？许可证？）、模型类型区分 pretrained / chat-finetuned、时间轴口径；
用 C6（或 C5）建立 Loss→Benchmark 映射并按可比性等级区分；对 C8 至少做一项逐任务
聚合分析，不得只用汇总表；必用 C1（或 C2）+ C3 + C4。

### 2.2 数据实况（决定思路能不能落地）

- **C1** 4 576 个模型，6 个维度（IFEval/BBH/MATH-L5/GPQA/MUSR/MMLU-PRO），提交日期
  2024-06 ~ 2025-03（仅 9 个月！），Type 字段可直接区分 pretrained(275) / chat(718) /
  fine-tuned(1785) / merges(1724)。**时间跨度太短，单靠 C1 无法做多年趋势**。
- **C3** 在 C1 基础上补了 26 条 2019–2023 的历史点（GPT-2/GPT-3 等，Source 标注为
  "Historical"），是时间轴的延伸，但属"混合"性质，需降级使用。
- **C4**（Epoch）1 961 个语言模型，864 个有训练算力，`Model accessibility` 字段直接给出
  开源口径（Open weights unrestricted / restricted / non-commercial / API / Unreleased）；
  年度最大训练算力 2019→2025 从 10^22.5 升到 10^26.7——这是"算力增长"情景的依据。
- **C6** 75 条桥接，仅 7 条 High（Pythia 同验证集），68 条 Medium；Loss–Average
  相关 **−0.51**（负相关，Loss 越低得分越高，与陷阱说的 +0.68 相反）。
- **C8** 1 863 个模型目录，每个 JSON 含 44 个任务（leaderboard_bbh_* 等子任务）及
  stderr，可做逐任务聚合。

### 2.3 实现步骤

**Step 1｜口径先行（为什么：题目逐条点名，缺一条就是硬伤）**

- 综合能力度量：主口径用 C1 的 `Average`（六维等权），副口径用 C8 逐任务重算的
  "去饱和平均"（下述 Step 5），两者对照。
- 开源筛选：以 C4 的 `Model accessibility ∈ {Open weights (unrestricted), (restricted use),
  (non-commercial)}` 为"开源权重"，再以 C1 的 `Hub License` 判许可证是否允许研究复现
  （apache-2.0/mit/llama3.x 等允许；cc-by-nc 标注为"研究可、商用不可"）。三档分别报。
- 模型类型：C1 `Type` 字段，pretrained 与 chat/finetuned **分开建模、分开预测**；
  merges 与 multimodal 剔除（不是"技术进步"的可比样本）。
- 时间轴：C1 用 `Submission Date`（提交日），C3 历史点用发布年，C4 用 `Publication date`；
  以提交日为主口径并说明"提交滞后于发布"的偏差方向。

**Step 2｜Loss → Benchmark 桥接（为什么：前三问的产出是 Loss，题目要求翻译成得分）**

对 C6 的 75 条按可比性分层拟合 sigmoid/logistic 型映射
`S = S_max / (1 + exp(κ(L − L₀)))`（得分有上下界，不能用线性）。High 层 7 点定形状锚，
Medium 层加权（权重 0.5）扩展范围；报两层各自的残差与整体 RMSE。还要按维度分别拟合
（MATH-L5、GPQA 对 Loss 更陡，IFEval 更平），因为综合分的映射误差主要来自维度异质。
**映射误差传播**：把桥接残差作为噪声源，蒙特卡洛传到最终预测区间，这就是题目要的
"讨论映射误差对结论的影响"。

**Step 3｜规模 vs 技术进步的分解（为什么：这是本问核心；"直接 ARIMA"是陷阱）**

主模型：**时变截距的规模回归**（面板思路）

```
S_i = f( L̂(N_i, D_i, Q̄) ) + τ(t_i) + ε_i
```

其中 `L̂` 来自问题二标度律（规模部分，参数固定不重估），`f` 是 Step 2 的桥接映射，
`τ(t)` 是"同等规模下随时间的额外增益"——这就是非规模技术进步。用 C1+C3（时间）
和 C4（N、D、算力）联表；D 缺失的模型用 C4 的 `Training compute` 反解 D = C/(6N)。
分解方法：对前沿序列 S_max(t) 做 Shapley/顺序分解，规模贡献 = 固定 τ 只让 N、D 按
历史演进算得的增益，技术贡献 = 剩余；两种顺序取平均消掉路径依赖。

试算（C1 pretrained，272 个模型）：`Avg ≈ 7.85 + 6.24·log₁₀N + 0.039·月`，规模系数
**+6.24**（陷阱说 −6.2，符号反了），时间项每月 +0.04 分——9 个月窗口内技术进步贡献
微弱，这提示：**必须接入 C3 历史点和 C4 的多年算力序列，才能把 τ(t) 估稳**。
报告里要如实说明 9 个月窗口的局限。

对照模型（互相验证）：(a) 效率前沿法——按年份算"达到同一得分所需最小算力"的下降率
（即技术进步的"算力等效倍数"，Epoch 常用口径）；(b) 分位数回归看前沿（95 分位）和
中位数的技术进步率是否一致。三个口径给出的"技术进步占比"若在 ±15 个百分点内即算稳。

**Step 4｜前沿预测与不确定性（为什么：题目要"算力增长放缓情景 + 不确定性"）**

- 情景：从 C4 提取 2019–2025 前沿算力年增长率（约 ×3–4/年），"放缓"取增长率减半与
  减至 1/4 两档，"基线"延续历史。
- 预测 = 规模路径（情景算力 → 问题三最优配置 → 标度律 Loss → 桥接得分）
  + 技术路径（τ(t) 外推，用线性与饱和两种形式）。
- 不确定性三源叠加：标度律参数 bootstrap（问题二已有 `P2_bootstrap.npz`）、桥接残差、
  τ(t) 外推形式差异；输出 12/24 个月的 50%/90% 预测区间，pretrained 与 chat 分开。
- 上界检查：预测值不得超过各维度饱和上限（IFEval 已接近 90，MATH-L5 空间最大）。

**Step 5｜C8 逐任务聚合（为什么：题目"必用、不得仅用汇总表"）**

选一项有分析价值的：**任务饱和度分析**。从 1 863 个 JSON 读 44 个子任务的 acc 与 stderr，
按任务算前沿分位数随时间的斜率，识别哪些子任务已饱和（斜率≈0 且接近上限，如
bbh_boolean_expressions）、哪些仍在快速增长（math、gpqa 子集）。据此构造"去饱和综合分"
（剔除饱和任务或按剩余提升空间加权），与 C1 Average 对照——饱和任务会低估技术进步，
这直接影响 Step 3 的分解结果，是一项"不是为用而用"的逐任务分析。

**Step 6｜陷阱回应与检验**

- r 符号：报 C6 实测 −0.51 及 High 层 −0.40，说明"Loss 越低得分越高"。
- 规模系数符号：报 +6.24，并说明混入 merges/多模态后符号可能被污染，这正是需要按
  Type 分层的理由。
- 检验：留出 2025-01 之后的 C1 数据做时间外推回测；桥接映射做留一交叉验证。

**产出接口**：`P4_bridge_params.json`、`P4_decomposition.csv`（各口径占比）、
`P4_frontier_forecast.csv`（情景 × 时点 × 分位）、`P4_task_saturation.csv`。

## 3. 两问的工作量与顺序建议

问题三代码量小（核心就是 Step 1 的一维反解 + 二维网格），一天可完成含敏感性；
难点在写清结构性转移的定义。问题四数据工程重（C4 联表、C8 1 863 个 JSON 解析），
建议先做 Step 1 口径 + Step 2 桥接 + Step 5 C8 解析（这三步互不依赖可并行），
再做 Step 3 分解，最后预测。问题三的 `P3_optimal_config` 是问题四规模路径的输入，
所以三先于四。

代码建议放 `code_q3/`、`code_q4/`，产出 `outputs_q3/`、`outputs_q4/`，接口命名沿用
`P3_*`、`P4_*`，与前两问一致。
